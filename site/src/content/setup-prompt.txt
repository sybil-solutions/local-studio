Operating rules

2. Do not bypass security checks, code signing prompts, or ssh host-key verification.
3. Never cap generation length with max_tokens. With vLLM or SGLang, never disable CUDA graphs and never force eager mode.
4. Do not replace or stop an inference server or controller that is already running. Local Studio 2.x data and controllers can stay where they are.
5. Use the official installers from the download page. Do not build from source unless I ask.

Phase 5 - prove it works through the controller

The app starts its bundled controller on 127.0.0.1:18091. Read the fleet key from ~/.local-studio-t3/config.json into a variable without printing it, then check:

- GET http://127.0.0.1:18091/api/health returns HTTP 200.
- GET /v1/models with Authorization: Bearer <fleet key> lists the served model.
- POST /v1/chat/completions with model set to that id (or auto) returns a real answer.
- Settings → Local in the app shows this machine and the live model.
- One agent thread in the app completes a turn on that model.

If a check fails, diagnose and fix it, then rerun the check. Do not hide degraded behavior.
